## Как пользоваться

Открыть Blender. Аддон `Tripo3d_Blender_Bridge` уже включён и сохранён в настройках. Панель находится в 3D View → боковая панель **N → Tripo**; сервер запускается вместе с аддоном. В Tripo Studio открыть **DCC Bridge**, подключить Blender и отправить выбранную модель через экспорт.

### Unity

Открыть проект DiceForge и выбрать **Diceforge → Characters → Tripo → Open bridge (staging)**. Этот пункт гарантированно выключает размещение полученных моделей в сцене. Обычный пункт поставщика **Tools → Tripo Bridge** тоже доступен; панель должна оставаться открытой во время передачи.

В Tripo Studio подключить Unity через **DCC Bridge**, выбрать модель и **Export → Send to Unity**. Приём предназначен для режима редактора, не Play Mode. Текущий pipeline определён как **URP**.

Входящие модели сохраняются отдельно:

`Assets/_Project/07_Art/Characters/Incoming/Tripo/<имя модели>/`

При повторном имени создаётся отдельная версия папки. По умолчанию сцена и каталог персонажей не меняются. Переключатель **Place received model in scene** оставлять выключенным для штатного приёма кандидатов.

Пакет подключён через UPM как `com.tripo3d.unitybridge`, относительный путь `file:../tools/ThirdParty/TripoBridge`. Это проектная копия из предоставленного пользователем каталога; она переносится вместе с репозиторием. Состав локальных изменений описан в `tools/ThirdParty/TripoBridge/LOCAL_CHANGES.md`.

## Что исправлено в проектной копии Unity Bridge

- Получение файлов отделено от размещения в открытой сцене; переключатель хранится отдельно для этого проекта.
- Папка приёма перенесена в `Characters/Incoming/Tripo`.
- WebSocket callbacks проходят через очередь `EditorApplication.update`. Исходный `delayCall` откладывал фактический импорт до активации окна, из-за чего соединение успевало закрыться. После исправления полный локальный тест завершился примерно за секунду без дополнительного фокуса окна.
- Отключена автоматическая фоновая очистка старых папок импортированных моделей и общих временных каталогов. Очистка собственных временных файлов завершённой передачи сохраняется.
- Импорт в Play Mode отклоняется.

Копировать обновления поставщика поверх `tools/ThirdParty/TripoBridge` вслепую нельзя: сначала перенести эти изменения и повторить тест передачи.

## Studio Bridge и API — разные маршруты

Эти установленные **DCC Bridge** принимают экспорт из браузерного Tripo Studio. Для этой передачи API-ключ не вводился. Они не дают агенту автоматическую генерацию на оплачиваемом API. Ранее упоминавшиеся Tripo API-плагины и MCP-провайдер генерации относятся к отдельному маршруту с ключом и собственной оплатой.

Для первой модели используем [комплект Тиша](Tish-v1/index.html): отдельный фронт → Tripo Studio → Blender для проверки и доработки → FBX/текстуры → Unity. Сам факт доставки не проверяет топологию, веса, материалы и анимацию.

**Существующий пункт `Import selected rigged FBX` пока сразу назначает prefab в активный каталог.** Он не является безопасным просмотром кандидата. На следующем этапе интеграции разделить его на создание кандидата, проверку и применение с откатом — это остаётся в [общем плане](INTEGRATION_PLAN.md). На текущем этапе получения модели этот пункт не запускался.
