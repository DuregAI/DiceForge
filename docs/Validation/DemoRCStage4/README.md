# Demo RC — checkpoint / resume

Источник требований: `docs/DemoRC/v0.1/06_PRODUCTION_RC.md`, раздел «Сохранение и повтор».

## Реализовано

- Профиль хранит один активный checkpoint демо: версию схемы, подпись сценария, level/chapter/run/node, стабильный operationId результата, именованные позиции и exited, ход, текущий набор и остаток шагов, cursor последовательного мешка, состояние Рыжа и учебной попытки.
- Запись ждёт завершения движения героя, Рыжа и учёта действительного действия. Прерывание анимации оставляет предыдущий завершённый checkpoint. Неверный ввод и pass не засчитываются как освоение; законченный pass с движением Рыжа сохраняется отдельно.
- Возврат в текущий узел карты восстанавливает состояние без повторного проигрывания Move/MatchEnded событий. Имена фигур восстанавливаются отдельно от агрегатов доски, поэтому общая клетка и независимый выход не меняют личности героев.
- Рестарт создаёт новую попытку и operationId, записывает стартовую доску и показывает R02; знания и режим помощи сохраняются. Resume сохраняет attemptId, доказательства, pendingHint и бюджет текстовых исправлений.
- Несовместимые schema/сценарий/состав/кампания/данные возвращают начало текущего уровня с понятной репликой G_R01. Ранее пройденные уровни, награды и знания не удаляются. Checkpoint необязателен для старого профиля.
- Последний выход сохраняется как finished до финального диалога. Возврат продолжает незакрытый переход; закрытые целиком комиксы не повторяются автоматически. Запись награды объединяет локальные сюжетные флаги и знания с receipt и удалением checkpoint в одной атомарной транзакции.
- Ошибка записи сохраняет предыдущий checkpoint и показывает повтор сохранения. Writer не записывает состояние старого campaign run после сброса карты.

## Проверки

Финальный прогон в Unity 6000.6.0f1: **45/45**, без пропусков и ошибок ([demo.xml](demo.xml)). В него входят 9 проверок core checkpoint, 3 интеграционных сценария resume/restart/ошибки записи, полный проход L1–L6 с S00–S06, 17 проверок кампании, 5 проверок препятствий, 8 проверок обучения и 2 проверки совместимости/атомарного результата.

Отдельная регрессия прогресса: **39/39** ([progression.xml](progression.xml)). Проверены сбой перед атомарной заменой профиля, повтор результата, объединение локальных сюжетных флагов с наградой, удаление checkpoint после загрузки с диска и старый профиль без новых полей. Все три интеграционных сценария checkpoint прошли в финальном прогоне, включая отказ записи из старого campaign run после сброса карты.

Кадры сквозного прохода: [L5 после первого действия](level-05-one-action-left.png), [S03](S03-frame-1.png), [финал S06](S06-wedding.png). Они иллюстрируют текущую презентацию; точное восстановление состояния и отсутствие повторной награды проверены интеграционными тестами выше.

Интеграционные тесты используют отдельный временный профиль и выключают внешнюю синхронизацию только в тестовом окружении, чтобы admin-reset из backend не менял подготовленную кампанию. Настоящий профиль, язык и Random восстанавливаются после проверки.

## Повторить вручную

На L5 сделать одно действие, выйти на карту и вернуться в текущий узел: остаётся одно действие, Рыж остаётся на прежней клетке. После второго действия Рыж двигается один раз. На L3 сначала вывести Луму: после возвращения Тиш остаётся на своей клетке, Лума — вышедшей. Прервать последний прыжок и отдельно завершающий комикс: первый случай возвращает предыдущий checkpoint, второй продолжает завершение без новой награды.

Следующий производственный блок — финальные модели/портреты персонажей и оформление локаций. Прежняя ошибка сохранённого освещения FirstTrail8 не относится к восстановлению доски и остаётся открытой. WebGL-сборка и приёмка на устройствах в этот этап не включены.
